3. Conflicts and questions for you

None of these were changed. Each needs your decision, or a schema change.

3.1 Branch and version links are lost through the cloud

dataThe cloud is the master copy, but three links do not survive it:

• fork (which scene a branch came from) and versionOf (Branch as new version) are never uploaded. SK.cloudPlan sends name, scale, tags, items, metadata and the parent only.

• The parent link goes up as parent_local_id, but fromCloudRow() brings every cloud detail back with parentId: null. A branch opened from the cloud on another device no longer knows its parent, so Merge into parent is gone there.

Suggestion: carry fork and versionOf in the row's metadata, as the rating already is (no new column), and map parent_id back to the parent's local_id on download.

3.2 The lane model is built but not loaded

featuresketch/lanes.js (labels such as 4B.6, versions) has tests, and branches already record fork, but the page does not load the file. Nothing on screen uses it yet. The code map flags it on its page and in the load order.

Question: wire it in now (labels in the Log and on library cards), or leave it as a model until the branch view is designed?

3.3 The app parts are globals

structureSplitting a closure into plain scripts puts about 315 names on window. That keeps every line as it was and works from file://, which modules do not. But a later library, or a new part, that declares the same top-level name would silently replace one.

Guard in place: tests/app-parts.js fails on a name declared twice or one that shadows a browser global. Later option: move the shared state into one App object, part by part, now that the browser smoke test can check each step.

3.4 One name or three

namingThe product is Quick Detail, the page title is "Wall Sketch", several file headers say "Sketch v3", the data export says app: 'wall-sketch', version: 3, and the database is wallsketch.

Suggestion: rename the title, headers and export label to Quick Detail. Never rename the IndexedDB database: every saved detail on every device lives under that name.

3.5 Two kinds of dialogs

uiDeletes and tag edits use the app's own pop-ups. Save as, Accept image, dimension text, Merge, Empty bin, Delete for good and the cloud-copy question still use the browser's prompt and confirm. Those look different, cannot be styled for the iPad, and some browsers block them in embedded views.

Question: move them all to the app's pop-ups?

3.6 Stylesheet layers

cssRules were appended over time, so a component's look is spread across files. The left bar, for example, is set in left-bar.css and refined again in later.css. The split keeps that order on purpose. Consolidating by component is now safe to try, since the screenshot comparison can prove nothing moved.
