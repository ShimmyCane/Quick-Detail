Quick Detail: code map

How the app is put together, where each part lives, and where to find each function. Open a file's page for its sections, its functions with line numbers, and which files use each one. The findings of the v5 compaction review, and the open conflicts, are in review notes.

1. How a drawing flows

1 · Input

Pen, finger, mouse and keys. input.js routes pointers; rail.js wires the bars and keys.

2 · Tools

tools.js draws strokes, erases, picks and drags handles. draft.js runs the text, dimension and hatch steps.

3 · One change

Every edit is commitPut, commitDel or commitReplace in changes.js. Each pushes an undo step and logs an event.

4 · After a change

changed() saves soon (details.js → IndexedDB and the JSON parallel), rewrites the live file, refreshes the chips and calls redraw().

5 · Paint

canvas.js → SK.paint (paint.js), which draws notes and dimensions from annot.js and hatches from hatch.js.

↓ the same events feed ↓

Recording

A take starts with the pen (recording.js) and stores the events, with sound and speech from record.js. SK.stateAt and SK.segment (core.js) replay it and split it into scenes.

Log and replay

log.js: a film strip of every scene; Replay, Restore and Branch from a scene.

Library and cloud

library.js and its neighbours list, rate, tag and bin details. cloud-ui.js → cloud.js uploads to Supabase.

Exports

export.js: PNG, JPEG with metadata (analyze.js), scene series, data and parallel JSON. GIFs use gif.js.

The sheet is in real inches. A detail's scale sets only how big text, arrows and ticks are, so they keep their size on paper (units.js).

3. Load order

The page loads the libraries first, then the app parts. The app parts are plain scripts that share one global scope: a function in one part can call a function in any other, at run time. Code that runs while the page loads (wiring a button, for example) may use only parts loaded before it. That is why start.js, which opens the first detail, is last. tests/app-parts.js checks the list and catches a name declared twice.

4. The data

Detail

{ id, name, scale, tags, items, parentId, fork, versionOf, rating, created, modified, deletedAt }

Made by newDetail() in details.js. The open one is the global detail.

Items

stroke (pen line), note (text with leaders), dim (ortho, aligned or angular), hatch, image (underlay), block (another detail, as an underlay).

Kept in detail.items, in draw order. item.meta holds element tags.

Recording (session)

{ id, detailId, created, duration, scale, base, events, speech, voice, audio, audioOffset }

Events are put, del, replace and mark (new scene).

Storage

IndexedDB wallsketch v2 (store.js): details, sessions (index detailId), parallels, kv (settings, customTags, currentDetail).

Pen colour and weight: localStorage['qd.pen'].

Cloud

Supabase tables sketch_details, sketch_recordings, sketch_snapshots, table_index; bucket sketch-media.

cloud.js; SQL in docs/supabase-sketch.sql.

7. Changing the code safely

  • Bump the ?v= value on every src and href in index.html whenever any file in sketch/ changes. tests/app-parts.js fails if they differ.
  • A new app part goes in sketch/app/, starts with a // Quick Detail app — Title. line, and gets a <script> tag before start.js.
  • Top-level names in sketch/app/ are global. Pick names that say what they are, and do not reuse one for a local variable that hides a global helper (byId, W, H, el).
  • Every edit to the open detail goes through commitPut, commitDel or commitReplace, so undo, the recording and saving stay in step.
  • A user-visible change gets a line in sketch/app/changelog.js.
  • New maths goes in a pure file in sketch/ with a Node test.
  • Run every test, then node tools/codemap.js to refresh this map.
